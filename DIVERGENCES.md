# Known divergences from the TypeScript implementation

| Area | TS | Rust | Why |
| ---- | -- | ---- | --- |
| Local DB | embedded pglite (`~/.horus/horus.db`) | embedded SQLite (`~/.horus/horus-rust.db`) | no embedded Postgres for Rust; separate file so both CLIs can coexist |
| JS/TS config modules (`core::config::load_config`) | `import()` for `.js`/`.mjs`/`.cjs`, jiti for `.ts` (the built `index.cjs` cannot load `.ts`: `Cannot find module '../dist/babel.cjs'`; source mode works) | evaluated by the installed `node` (`--experimental-strip-types` for `.ts`: Node ≥ 22.6, erasable TS syntax only) through an inline loader that prints `JSON.stringify(mod.default)`; no `node` on PATH → error naming the file and suggesting `.horus/config.json`. The default export crosses as JSON (functions/`undefined` drop, `NaN` → `null`); module-not-found text ends `imported from …/[eval1]` | no JS runtime in Rust |
| Executable name | `horus` | `horus-rs` (Cargo `[[bin]]`); clap `bin_name = "horus"` keeps usage/help/messages identical to TS | ships alongside the TS CLI (npm `@merittdev/horus-rs`, formula `horus-rs`) without shadowing `horus` |
| `HORUS_VERSION` (`core::version`) | injected from `apps/horus/package.json` by tsup, `'dev'` otherwise | compile-time `HORUS_VERSION` env var, `"dev"` otherwise; `SOURCE_PIN_ENFORCED` is a `const` derived from it | no package.json at build time; set `HORUS_VERSION=x.y.z cargo build` in release packaging |
| `defineConfig` helper | identity function for TS type inference | not ported | no equivalent need in Rust |
| `queue_hygiene::filter_queue_edges` | generic over any object with the `QueueEdgeLike` fields | generic over the `QueueEdgeLike` trait; consumer edge types implement it | structural typing has no Rust analogue |
| Secrets `EncryptedSecret` guard | `isEncryptedSecret(v)` type guard | `EncryptedSecret::from_value(&Value) -> Option<_>` (plus `is_encrypted_secret`) | same acceptance rules; envelope bytes identical (verified against a TS-written `secrets.local.json`) |
| `LocalConfigFile` / `LocalSecrets` unknown keys | preserved in place by `JSON.parse`/`JSON.stringify` | preserved via `#[serde(flatten)] extra`, re-serialized after the known keys | serde cannot keep the original position of unknown keys |
| `ai::contract` verdict / uncertainty | string unions; `validateNarrative` reports invalid verdict / uncertainty strings | closed enums `HypothesisVerdict`, `Uncertainty` (serde lowercase); those two validation errors are unreachable. Anthropic parsing still maps unknown strings to `unconfirmed` / `high` like TS | type safety; the CLI builds these from engine enums |
| `ai::contract::NarrativeOutput.whereNext` | may be `undefined`; `validateNarrative` mutates it to `[]` | plain `Vec<String>` with `#[serde(default)]`; `validate_narrative` takes `&NarrativeOutput` and does not mutate | missing field already deserializes to `[]` |
| `ai::anthropic` fallback truncation | `raw.slice(0, 4000)` (UTF-16 code units) | first 4000 `char`s | Rust strings are UTF-8; only differs on astral-plane characters |
| `ai::interpretation::InterpretationResult` JSON key order | not-ok with `model`: `ok, command, promptKind, model, provider, warning` | always `ok, command, promptKind, provider, model, text, warning` | one struct serves both branches; same keys, `model`/`provider` swap only on the warning branch |
| `ai::provider_execution` adapter errors | `ProviderRunResult` discriminated union `{ok, output} \| {ok, error}` | enum `ProviderRunResult::{Ok, Err}` with a manual `Serialize` emitting the same `{ok: bool, output \| error}` shape | no anonymous unions in Rust |
| `ai::local_providers::LocalProviderLookupResult` | `{found: true, provider} \| {found: false, id}` | enum `Found(&Descriptor) \| NotFound(String)`, not serialized | internal lookup result; the CLI prints its own text |
| `ai::anthropic` HTTP error text | `${status} ${statusText}` from fetch | `status.as_u16()` + reqwest `canonical_reason()` (empty for non-standard codes) | reqwest does not expose the server's reason phrase |
| `ai` fixtures / registries | plain `const` objects | `LazyLock` statics (`FIXTURE_*`, `DETECTION_FIXTURES_*` as `IndexMap`, `DEFAULT_LOCAL_PROVIDER_REGISTRY`) | heap-allocated `String`s cannot be `const` |
| `db` schema types (`migrations_bundle`) | Postgres: `uuid`/`jsonb`/`timestamptz`/`text[]`/`boolean`/`real` | SQLite: `TEXT` v4-uuid default expr / `TEXT` JSON (stored verbatim) / `TEXT` ISO-8601 `YYYY-MM-DDTHH:MM:SS.mmmZ` / `TEXT` JSON array / `INTEGER` 0-1 / `REAL`; FKs folded into `CREATE TABLE`/`ADD COLUMN` (SQLite has no `ADD CONSTRAINT`) | same table/column names and the same 16 migration tags in `__horus_migrations` |
| `db` memory-sync triggers (migration 0013) | plpgsql triggers guarded by session setting `current_setting('horus.sync_pull')`; one multi-event trigger per table | SQLite triggers (one per event; `memory_changed` is AFTER UPDATE rewriting the row) guarded by `__horus_settings` row `key='horus.sync_pull', value='1'` | no session variables or BEFORE-trigger `NEW` assignment in SQLite; single-writer lock makes a DB-scoped flag equivalent |
| `db` writer lock files | `horus.db.lock`, `horus.db.lock.owners/`, `horus.db.lock.reap` | `horus-rust.db.lock`, `horus-rust.db.lock.owners/`, `horus-rust.db.lock.reap`; same bakery/ownership algorithm | separate DB file ⇒ separate lock namespace; the TS lock files are never touched |
| `db` display-only fallback (`open_db`) | only missing pglite assets degrade to the unavailable handle; corruption/permissions propagate | `rusqlite::Connection::open` failure degrades to `DbHandle::unavailable()` (`HORUS_DB_UNAVAILABLE` on every `with_conn`); migration errors and `HORUS_DB_BUSY` propagate | bundled SQLite has no missing-asset case; "cannot be opened" is the nearest equivalent |
| `db` query surface | drizzle `HorusDb` used freely by engine/CLI | `DbHandle::with_conn(FnOnce(&rusqlite::Connection))` on `spawn_blocking`; typed helpers for investigations/outcome/queue; other tables via raw SQL | no ORM; JSON columns are `String` so saved payloads round-trip byte-identically |
| `knowledge` schema validation | zod `parse` reports every structural + constraint issue with its path | serde reports the first structural error (`parse <file>` context); `validate_snapshot` / `validate_manifest` then collect zod-style constraint issues (`min(1)`, `datetime()`, `literal(1)`, `max(20000)`, `0..=1`) as `path: message` | serde_json stops at the first structural error |
| `knowledge` JSON numbers (`sourceRelationships[].confidence`) | `JSON.stringify` prints integral floats as `1` | `Option<f64>` with `schema::js_number` serializer prints integral values as `1` (not `1.0`) so `knowledge-base.json` and its manifest `contentHash` are byte-identical to the TS store (verified against a real 12 MB project index) | serde_json prints `1.0` by default |
| `knowledge` query items (`KnowledgeMatch.item`) | `Record<string, unknown>` (the zod-parsed object) | `serde_json::Value` object produced by serializing the typed item; search/find semantics, category order, limit and tie-breaks identical | Rust has no structural object type; one conversion keeps `query.rs` a line-for-line port |
| `knowledge` `KnowledgeFile` | string-keyed `KNOWLEDGE_FILES` record | `KnowledgeFile` enum + `file_name()` | idiomatic Rust; same file names |
| `knowledge` import error text | `Not a Maison Safqa knowledge-base: <zod issue>` / `Could not parse <file> as JSON: <V8 message>` | same prefixes; the first-issue text is reproduced for the common cases (`Expected object, received string`, `Expected array, received …`, `Invalid input`), the JSON parse detail is serde's | no zod/V8 in Rust |
| `knowledge` `kbVersion` from a float `version` | `String(1.0)` → `"1"` | serde `Number::to_string` → `"1.0"` | JS numbers have no int/float distinction |
| `knowledge` `importKnowledgeBaseFile` result | flat `{ ...ImportResult, contentHash, manifest }` | `ImportFileResult { result: ImportResult, content_hash, manifest }` | no spread in Rust structs |
| `source::lifecycle` process signalling | `process.kill(pid, 'SIGTERM'/'SIGKILL'/0)` | shells out to `/bin/kill -TERM|-KILL|-0 <pid>` | no `libc`/`nix` dependency in the workspace; same escalation + 15×200ms liveness poll |
| `source::lifecycle::SourceHostRecord.port` | `NaN` when `host.json` has no numeric port | `Option<i64>` (`None`) | same `isFinite && > 0` checks; the record is never serialized |
| `source::lifecycle::start_host` detach | `spawn({ detached: true }).unref()` | `process_group(0)` + never waited (unix only) | same effect: host survives the CLI exiting; log fd appended to `.horus/source-host.log` |
| `source::lifecycle::analyze_repo` timeout error | `err.killed || signal === 'SIGTERM' || code === 'ETIMEDOUT'` | `tokio::time::timeout` elapsed → child killed | same message text; exit-by-signal for other reasons reports as "analyze failed" with the stderr tail |
| `source::client::SourceHttpClient` timeouts | AbortController per attempt; aborts rethrown unretried | `reqwest` per-request timeout; `is_timeout()` unretried, other transport errors retried with the same 150·2ⁿ ms backoff | reqwest has no abort signal |
| `source::client::SourceHttpClient` error text | Node `fetch`: a timed-out (aborted) request throws `This operation was aborted`, a transport failure `fetch failed`; a non-JSON 2xx body throws V8's `SyntaxError` text | same two strings (`changes`, `--json` `detail`, connector-failure classification all read them); a body that fails to decode keeps serde's message | no V8 `JSON.parse` in Rust |
| `source::memory_index::MemoryVectorIndexLike` | structural TS interface | `async_trait` object trait; `fallback: Option<Arc<dyn MemoryVectorIndexLike>>` | Rust has no structural typing — the engine crate must `impl` the trait for its `NoopVectorIndex` |
| `CodeProvider` optional methods (`class_methods`, `overview`, …) on `SourceCodeProvider` | always present | return `Ok(Some(..))` per the contract's `Option` convention | contract models TS `?` methods as `Option` results |
| `lens::provider::LensReportSignal.error_count` / `LensReportSummary.error_count` | JS `number` | `f64`, emitted through `jsutil::normalize_js_numbers` so `3` serializes as `3` not `3.0` | `Number(v)` can be fractional for a malformed row; integer output parity preserved |
| `lens::provider` `Date.parse` | JS `Date.parse` (lenient) | `jsutil::parse_date_ms` (RFC 3339 / ISO forms / bare date) | the cloud emits ISO-8601 only |
| `shopify::client::ShopifyGraphQLError` | `{ message; [k: string]: unknown }` | `message` + `#[serde(flatten)] extra` | preserves the `extensions.code` THROTTLED check and any other upstream keys |
| `git::provider` sort stability | `Array.prototype.sort` is stable | `sort_by` (stable) on insertion-ordered tallies | identical ordering for ties |
| `sqlserver::SqlServerStateClient` | always built (`mssql`) | cargo feature `sqlserver`, ON by default (the CLI builds it, so `connect sqlserver` probes and `additional_state_for_env` includes it); `--no-default-features` drops it, and then the factory errors for a `sqlserver` connector | lets a build skip `tiberius`, which compiles `aws-lc-sys` (native C) through `tokio-rustls` |
| SQL Server connection string | `mssql.ConnectionPool.parseConnectionString`: ADO only — mssql 12.7.2 returns an empty config for a `mssql://` URL, so the probe fails with `The "config.server" property is required and must be of type string.` (verified against `infra/` SQL Edge) | ADO via `tiberius::Config::from_ado_string`; `mssql://`/`sqlserver://` URLs also accepted, parsed by hand (host/port/user/pass/db, `encrypt`, `trustServerCertificate`) | tiberius has no URL parser; accepting the URL form is a strict superset (TS is broken for it) |
| SQL Server `Encrypt=false` | tedious TLS-wraps only the login packet and never validates the server certificate | `EncryptionLevel::Off` + `trust_cert()` (unless `TrustServerCertificateCA` pins a CA); URL `encrypt=false` maps to the same (was `NotSupported`) | tiberius `Off` validates the login-TLS cert and rustls rejects SQL Server's self-signed X.509 v1 cert (`UnsupportedCertVersion`), so a working TS config failed in Rust |
| SQL Server error text | tedious: server errors print the server message; a failed login reports the LAST error token (`Login failed for user 'x'.` even when the database is missing); refused → `Failed to connect to h:p - Could not connect (sequence)`; untrusted cert → `Failed to connect to h:p - self-signed certificate; if the root CA is installed locally, try running Node.js with --use-system-ca` | server errors print the token message; tiberius stops at the FIRST error token, so a missing database reads `Cannot open database "x" requested by the login. The login failed.`; refused matches; certificate rejection reads `Failed to connect to h:p - the server's certificate was rejected during the TLS handshake: …` (first sentence of tiberius's text) | tiberius exposes only the first login error; rustls and Node word certificate failures differently |
| Postgres error text (`postgres::client`) | node-postgres: the server message (`password authentication failed for user "x"`, `database "x" does not exist`), Node socket text (`connect ECONNREFUSED h:p`), `The server does not support SSL connections` | same strings, mapped from tokio-postgres (`as_db_error().message()`, the io cause, the TLS-unsupported cause); TS's pg-connection-string `sslmode` SECURITY WARNING on stderr is not reproduced | tokio-postgres's Display is `db error` / `error connecting to server` |
| Postgres TLS (`postgres::client`) | node-postgres: TLS only when `sslmode`/`ssl` is set; `no-verify` skips cert checks | same rules, implemented via `tokio-postgres-rustls` (webpki roots; `no-verify` → unverified) — `sslmode` is stripped from the URL before tokio-postgres parses it | tokio-postgres defaults to `prefer` and rejects `no-verify` |
| Postgres `MAX(date_col)` for `timestamp`/`date` columns | node-postgres parses as process-local time, then `toISOString()` | read as UTC | no process-local timezone semantics; identical when `TZ=UTC` |
| Postgres `MAX()` on non-date/text/number types | `String(v)` of the driver value | re-queried as `MAX(col)::text` | Postgres text form instead of node's JS formatting |
| Mongo record JSON (`MongoStateClient::records`) | `JSON.parse(JSON.stringify(rows))` via bson `toJSON` | `bson_to_js_json`: ObjectId → hex, Date → ISO ms, Binary → base64, ints/doubles → numbers; Decimal128/Timestamp/Regex etc. → relaxed extended JSON | bson-rs has no `toJSON` |
| Mongo `groupBy` `_id` of Date type | `String(date)` (JS locale date string) | ISO-8601 | locale output is not reproducible; status fields are strings in practice |
| Redis clients (`redis::scan_client`, `bullmq::client`) | ioredis: lazy connect, 5s connect timeout, max 3 reconnect attempts, no response timeout | `redis` multiplexed connection: lazy, 5s connect timeout, 10s per-response timeout. Error TEXT matches ioredis: connection-level failures (refused, unreachable, timed out, dropped) print `Reached the max retries per request limit (which is 1). Refer to "maxRetriesPerRequest" option for details.`; server replies print Redis's raw `CODE detail` (`WRONGPASS …`, `NOAUTH …`). | Redis keys/values | JS strings (UTF-16, `slice` by code unit) | bytes decoded lossily; `failedReason` truncated by `chars().take(120)` | keys are not guaranteed UTF-8 |
| `state::StateClient` trait | `StateClient` + `{ health(); close() }` intersection on the provider side | `health`/`close` are part of the trait | every client implements both |
